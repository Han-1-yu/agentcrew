## 三、两条真实发现（不是回归，是产品行为边界）

### 发现 1：文档类契约的 `must_contain` 是**逐字**匹配，语义等价表述不算命中

`doc-changelog` 的第 12 条 case 要求产物「含迁移步骤」，PM 把 `迁移步骤` 写进
`must_contain`，G1 在 `agentcrew/gate/static_checks.py:128-138` 做的是
`needle.lower() in content.lower()` ——**字面包含**。而模型实际产出是：

```
## 5. 分步迁移路径（v1.4 → v1.5）
| 步骤 | 动作 | 验证方式 | 可独立执行 |
```

语义上完全有迁移步骤，只是没有**连续出现「迁移步骤」四个字**。返工 3 轮、每轮
hint 都是「在 docs/migration-design-v1.5.md 中定义 迁移步骤」，模型始终改写措辞，
最终 run failed。

- **性质**：门禁按契约办事、判定可解释；问题在于「自然语言文档 + 字面符号契约」
  这一组合本身不可靠，且返工 hint 对文档不贴切（「定义」用于代码符号才合适）。
- **可选处置**（需产品拍板，本轮**未改**）：把 hint 文案改成「逐字包含以下文本：{needle}」，
  并同步 `tests/test_gatekeeper.py:239`、`:307` 的断言；或让 PM 在文档类 case 上减少
  `must_contain`、改用 `artifact_matches` 正则。**改 hint 文案是引导而非放宽门槛**，
  不削弱 G1。

### 发现 2：规划期 fail-fast 会挡住「驳回类」用例的取证路径

`reject-empty-json` 的目标是「交付 0 字节 JSON」，PM 两次规划都被自己的校验拦住：
先要求 T2 产出文档而交付物里没有文档类文件（标准自相矛盾），再让 T1/T2 同时声明
`data/blank.json`（路径冲突）。两条都是**正确的 fail-fast**（`plan_rejected`），但
用例因此停在规划阶段，验证不到 G1。

- 同族证据已由 `reject-empty-file`（首批）与 `reject-empty-py`（本轮）补上：
  0 字节产物在三轮内被 static 层以「为空文件」拒绝，run 按预期 FAILED。
- **待办**：或调整该 case 的 goal（明确「一个任务产出、不要文档」），或让驳回类
  用例把「规划期失败」与「门禁拒绝」分开断言（需要新 check kind，属产品决策）。

```bash
python scripts/regrade_eval.py examples/evals/capability-live-rest-a.jsonl \
    --output-dir output/_eval --since 2026-11-13T14:50
```

`scripts/regrade_eval.py` 与 `run_case` 同口径读盘（`run.json` / `ledger.jsonl` /
`artifacts/`），把 run 级 `error` 也带回 `CaseOutput`：**运行失败时所有断言一律
判失败**，防止「跑崩了但 artifact_not_contains 恰好通过」的假绿。`--since` 用于排除
同一 case 的历史 run 目录（不传会取到旧结论，本工具自身踩过这个坑）。
