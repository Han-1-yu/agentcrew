## 二、潜在风险（逻辑成立，未稳定复现）

### P3-1 `web_fetch` 的 DNS rebinding 窗口（TOCTOU）

`agentcrew/tools/network.py:130-148`：先 `getaddrinfo` 解析并校验全部 IP 拒绝私网，随后 `opener.open(request)` **再次独立解析 DNS** 并连接。两次解析之间域名可切换（TTL 0 轮换公网/私网记录）→ 校验通过但连接到私网。直连 IP/localhost 检查是稳的（实测拒绝 127.0.0.1 / 169.254.169.254）。**前提是攻击者控制目标域名 DNS**——正常使用不触发。修法方向：解析后按 IP 直连（Host 头保留）或复用已校验的 `socket`。

**处置（2026-11-21）**：`getaddrinfo` 结果一次校验、取第一个合法 IP 用
`socket.create_connection` 直连；HTTPS 用 `ssl.create_default_context()` +
`server_hostname=原域名` 做 SNI 与证书校验（证书仍锚定域名，IP 只是传输地址），
请求由 `http.client` 发出（`Host` 头按原域名生成，虚拟主机不受影响）。3xx/4xx/5xx
仍以 `HTTPError` 抛出，错误文案与旧 opener 路径一致；不跟随重定向的语义由
「不跟随」改为「显式拒绝」（同一个出口行为）。回归六例：三个 `_pick_public_ip`
语义例、私网解析在建连前拒绝（`create_connection` 被碰即失败）、校验 IP 直连 +
Host/path 保真的本地回测端到端、4xx 仍是 `HTTPError`。

### P3-2 队列 `_finish` 在 claim 缺失时不校验归属

`agentcrew/runtime/queue.py:215-223`：`claim is None` 时直接放行收尾。若 worker 心跳失败后租约被 `requeue_stale` 回收（claim 被删/换主），旧 worker 的 `complete()/fail()` 仍会写 `done/failed` 并删掉 `pending` 条目——与新 worker 双写竞争。需要「心跳失败 + 回收 + 旧 worker 仍在收尾」三者重叠，概率低但存在。修法方向：claim 缺失时视为「租约已失」，拒绝收尾并留痕。

### P3-3 时间守卫可被变量赋值绕过（守卫健壮性）

`tests/test_time_migration_guard.py` 的 `_WRITE_PATTERN` 只匹配字面 `= datetime.now()`；`now = datetime.now()` 后 `updated_at=now` 不命中——entity.py（P2-2）已实际利用此缺口。守卫可加二级扫描（局部变量来源追踪）或对高危文件做 `utc_now` 白名单断言。
