# ADR-0001：认证 fail-closed —— 无密钥一律拒绝启动

- **状态**：已接受（2026-11-08）
- **关联**：`THREAT_MODEL.md` T-01 / §6 认证行；`api_auth_enabled` 默认 `True`

## 背景

此前 `api_auth_enabled` 默认 `False`：不改配置，`serve --host 0.0.0.0` 就是匿名可
管全站——最常见的上线事故是「忘了配」。第一版加固把「无密钥 + 回环」做成「警告后
放行」，立即被既有用例打回：`AGENTCREW_API_AUTH_ENABLED=1` 却无密钥的用例不是退错，
而是把进程挂在启动后的等待上。

## 决策

判定只看「有没有密钥」与「要不要认证」，不猜「是不是显式设置的」：

1. 有密钥（legacy / `--api-key` / RBAC 密钥库有活跃密钥）→ 认证必开；
2. 无密钥且认证开（默认）→ **退 3**，回环也一样；
3. 无密钥且显式关认证 → 只允许绑回环并警告，绑非回环仍退 3。

## 后果

- 得到：认证状态由「有没有密钥」这一可观测事实决定，日志里不会再出现「我以为开了、
  其实匿名裸奔」这种歧义。
- 付出：本机快速调试也得先 `keys add` 或显式 `api_auth_enabled=false`，多一步。
- 重审：出现「密钥库可热加载」且要求「零配置本机秒起」的强需求时，再评估例外。
