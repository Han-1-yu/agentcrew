# ADR-0002：`run_python` 默认不注册

- **状态**：已接受（2026-11-08）
- **关联**：`THREAT_MODEL.md` G-9；`code_exec_enabled`（默认 `False`）

## 背景

`run_python` 有进程级隔离（`-I`、裁剪环境变量、`cwd` 限制、超时杀进程），但**没有
网络隔离、没有 CPU/内存上限、没有系统调用沙箱**——模型生成的代码可以出网、可以吃满
资源。把「执行模型生成的代码」当默认能力，等于把「配置错误」升级成「远程执行面」。

## 决策

- 默认**不注册** `run_python`；模型看不见也调不到。
- 显式 `AGENTCREW_CODE_EXEC_ENABLED=true` 才注册，且 run 装配 / 工具实验台 / CLI
  清单**三处同口径**（调试入口不能成为绕过开关的后门）。
- 容器级沙箱（Docker/gVisor）明确放到部署层，不在代码里假装做到。

## 后果

- 得到：默认面最小化；「忘了关」不再等于「可被远程执行」。
- 付出：真正需要代码执行的场景多一步显式开启，且开启后仍需自行套沙箱。
- 重审：引入容器后端（P3）时，本 ADR 的「默认关」仍保留，只替换沙箱实现。
