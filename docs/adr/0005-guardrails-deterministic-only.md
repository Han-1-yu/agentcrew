# ADR-0005：guardrails 只用确定性规则，不用 LLM 判

- **状态**：已接受（2026-11-08）
- **关联**：`tools/guard.py`；`tool_guards` 配置；`THREAT_MODEL.md` G-8

## 背景

「用模型判断模型的输出是否危险」既不稳定又贵，失败模式恰好是「该拦的没拦」。安全
拦截要的是确定性：同样输入永远同样结果，能被单测钉住。

## 决策

- guardrails 只支持**确定性判断**：正则 / 长度 / 字段定位，双相位（`input` 执行前、
  `output` 回灌前），三态（`block` / `warn` / `allow`）。
- `block` 的工具**一次都不执行**，原因与规则名回灌让模型自己改。
- 明确承认：正则可被变形写法绕过（双空格、base64、转义），guard 是「挡住明显的错」，
  不是沙箱——真正的边界是 `code_exec_enabled` 与 `tool_permissions`。

## 后果

- 得到：可测试、零成本、加载期就能校验规则是否合法。
- 付出：挡不住语义层面的恶意（需要 LLM 判的场景），那是明确不做的能力。
- 重审：若出现「低成本、可评估的语义判模型」，作为**补充层**接入，不替代确定性层。
