````markdown file=docs/PRD.md
# logstat · 产品需求

## 1. 背景

服务端排障时最常见的动作是「捞一个时间段的访问日志，看看有多少 5xx、慢在哪」。
现成的方案要么依赖 ELK 这类重平台，要么临时写 awk 一行行手搓、换个字段就重写。
logstat 只做一件事：把一段访问日志压成几行统计，用一条命令跑完，输出可直接贴进故障报告。

## 2. 目标用户

| 用户 | 场景 | 诉求 |
|---|---|---|
| 值班工程师 | 告警响了，先判断是不是 5xx 突增 | 一条命令出状态码分布，30 秒内给结论 |
| 后端开发 | 压测后看耗时分位 | 直接拿 p50/p95，不需要自己算 |
| 复盘作者 | 写故障报告需要量化证据 | 输出能被复制进 Markdown 表格 |

## 3. 统计口径

输入是每行一条的访问日志，字段以空白分隔，至少包含时间戳、状态码、耗时毫秒：

| 输出列 | 含义 |
|---|---|
| `total` | 成功解析的行数 |
| `skipped` | 无法解析而被跳过的行数 |
| `status` | 状态码到条数的映射，按状态码升序 |
| `p50` / `p95` | 耗时毫秒的 50 / 95 分位，取最近秩 |
| `window` | 按分钟聚合的时间序列，每项含该分钟的请求数与错误数 |

`skipped` 必须显式输出：日志里混进半行、混进启动横幅是常态，
把这类行静默丢掉会让总数与上游对不上，排查时反而制造新的疑点。

## 4. 命令形态

```
logstat analyze access.log
logstat analyze access.log --window 5m
```

默认输出为等宽表格；`--json` 输出同一份数据的 JSON，便于接进脚本。

## 5. 验收标准

- AC-01 给定 1000 行合法日志，`total` 等于 1000，`skipped` 等于 0。
- AC-02 混入 3 行残缺日志后，`total` 仍为 1000，`skipped` 为 3。
- AC-03 状态码分布之和等于 `total`。
- AC-04 `p95` 不小于 `p50`，且两者都落在输入耗时的最小与最大值之间。
- AC-05 `--json` 与表格输出描述同一批数字（逐字段相等）。
````
